## 첫 메시지에 붙여넣을 프롬프트

```text
Wiki Race 2.0 디자인 개편을 진행하려고 해.

첨부한 파일을 모두 먼저 읽어줘.

- `01-CONFIRMED-SPEC.md`: 확정된 게임 규칙의 단일 기준
- `20-DESIGN-BRIEF.md`: 유지할 시각 방향과 고쳐야 할 문제
- `21-SCREEN-MATRIX.md`: 화면·상태·PC/모바일 요구사항
- `Wiki 디자인 와이어프레임 1차.zip`: 기존 Claude Design 와이어프레임

이번 채팅에서는 프로덕션 React 코드를 바로 수정하지 말고 디자인 구조와 시안을 먼저 확정하고 싶어. 기존 와이어프레임을 전면 폐기하지 말고 각진 프레임, 얇은 구획선, 제한된 청회색 포인트, 큰 레이스 HUD, 경로 비교, 모바일 바텀시트 같은 장점은 유지해.

반드시 고칠 부분은 다음과 같아.

1. 싱글·1:1·그룹을 동등한 위계로 보여준다.
2. 랜덤·목표 지정·오늘의 세 코스와 게스트 흐름을 반영한다.
3. 싱글, 1:1 비아이템, 1:1 아이템, 그룹 게임 화면을 따로 설계한다.
4. 그룹은 3~8명, 무아이템, 3등 후 2분 grace, 전체 20분, 완주 후 관전을 반영한다.
5. 관전은 실제 참가자 화면을 기본으로 하고 경로 비교를 보조 보기로 둔다.
6. 관전 채팅은 없고 preset 이모티콘과 음소거만 있다.
7. 1:1 아이템전은 5슬롯과 공격·탐색·방어·조커 상태를 보여준다.
8. 결과에는 경로, XP, 레벨업, 일반·히든 업적 reveal이 들어간다.
9. 4부위 아바타 대신 프로필 카드 꾸미기를 설계한다. 시스템 아이콘/일러스트 4~6종 중 1개, 대표 칭호 1개, 대표 배지 최대 3개, 프레임 1개, 배경 1개, 경로 색상·효과, 완주 효과, 관전 이모티콘만 다룬다.
10. 사용자 이미지 업로드·복잡한 아바타 편집·아바타 프리셋·상점·재화·시즌·신고는 만들지 않는다. 상단 내비게이션은 닉네임·레벨·대표 칭호 중심이다.
11. Wikipedia 본문이 언제나 가장 큰 영역이어야 한다.

SaaS 카드 대시보드, 과도한 glass/neon, 본문을 덮는 장식은 피하고 PC와 모바일 모두 본문 가독성을 우선해. 본문 16px, 터치 대상 44px, 키보드 탐색, 색상 외 상태 구분, reduced motion도 포함해.

우선 다음 단계까지만 진행해줘.

1. ZIP 안의 현재 와이어프레임 화면과 시각 규칙을 목록화한다.
2. 확정 명세와 비교해 유지/수정/신규 화면을 표로 정리한다.
3. 전체 IA와 공통 컴포넌트 구조를 제안한다.
4. PC·모바일 와이어프레임 제작 순서를 제안한다.
5. 아직 애매한 디자인 선택만 질문하고, 이미 확정된 게임 규칙은 다시 묻지 않는다.

내가 구조안을 확인한 뒤 실제 수정 와이어프레임을 만들어줘. 이후 결과물에는 화면별 상태, 컴포넌트 규칙, 반응형 동작을 개발자가 구현할 수 있을 정도로 함께 작성해줘.
```

## 구조 승인 후 두 번째 프롬프트

```text
승인한 IA와 디자인 방향으로 Wiki Race 2.0 수정 와이어프레임을 제작해줘.

먼저 PC 핵심 흐름인 메인 로비 → 모드 설정 → 게임 4변형 → 관전 → 결과를 만들고, 다음으로 랭킹·프로필 카드·업적과 모바일 변형을 추가해. 프로필에는 시스템 아이콘 선택, 칭호, 배지 최대 3개, 프레임, 배경, 경로/완주 효과, 관전 이모티콘 inventory를 포함하고 legacy 이미지·기본 이미지·asset error·guest 상태를 구분해. 로딩·복구·연결 끊김·나가기 확인·grace·RETIRE·FORFEIT·빈 상태·오류·reduced motion 상태 보드도 포함해.

기존 와이어프레임의 시각 언어를 재사용하되 확정 기능과 맞지 않는 가짜 버튼·수치·모드는 제거해. 최종 결과에는 1) 수정 와이어프레임, 2) 디자인 토큰, 3) 공통 컴포넌트 목록, 4) 화면별 상태표, 5) PC/모바일 차이, 6) 코드 통합용 인수인계 문서를 제공해.

아직 프로덕션 저장소의 React 기능 로직은 수정하지 마.
```
