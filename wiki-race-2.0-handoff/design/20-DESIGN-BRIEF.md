# Wiki Race 2.0 디자인 개편 브리프

기준 문서: `../01-CONFIRMED-SPEC.md`  
기준 자료: `Wiki 디자인 와이어프레임 1차.zip`  
목표: 확정된 기능과 상태를 빠짐없이 수용하면서 Wikipedia 탐색이 중심인 게임 UI 설계

## 1. 디자인 목표

- 처음 보는 사용자가 싱글·1:1·그룹의 차이를 즉시 이해한다.
- 반복 사용자는 최소 클릭으로 원하는 모드에 들어간다.
- 게임 중 Wikipedia 본문과 링크가 가장 잘 보인다.
- 상대·참가자 상태를 읽을 수 있지만 본문을 가리지 않는다.
- 결과에서 순위·시간·이동 횟수·경로·XP·업적을 한 흐름으로 이해한다.
- PC와 모바일이 같은 기능을 제공하되 모바일은 문서 면적을 최우선으로 한다.

## 2. 유지할 1차 와이어프레임 요소

- 각진 프레임과 얇은 구획선
- 제한된 청회색 포인트 컬러
- 도면·계기판처럼 정보를 정돈하는 시각 언어
- 큰 타이머와 분명한 레이스 HUD
- 경로 노드를 시각적으로 보여주는 결과 화면
- 관전에서 참가자 경로를 비교하는 보조 보기
- 모바일 바텀시트 방향
- 과도한 장식 없이 본문을 중심으로 두는 밀도

1차 시안은 전면 폐기하지 않고 위 요소를 디자인 시스템으로 정리해 재사용한다.

## 3. 수정해야 할 1차 와이어프레임 요소

### 3.1 정보 구조

- 싱글·1:1·그룹을 동등한 위계로 표시한다.
- 그룹을 주력 모드로 과도하게 크게 보이게 하지 않는다.
- 그룹 선택 시 일반 `게임 시작`이 아니라 `방 만들기 / 코드 참가`를 보여준다.
- 1:1도 방 생성·참가와 아이템 옵션의 실제 흐름을 반영한다.
- 랜덤·목표 지정·오늘의 탐험을 싱글 내부에서 구분한다.
- 게스트 싱글 진입과 로그인 사용자 전용 기능을 구분한다.

### 3.2 게임 화면 변형

- 단일 그룹 게임 화면만으로 세 모드를 대표하지 않는다.
- 싱글, 1:1 비아이템, 1:1 아이템, 그룹의 HUD 변형을 각각 설계한다.
- 그룹에는 아이템 슬롯을 표시하지 않는다.
- 1:1 아이템전에는 5슬롯, 공통 쿨타임, 지속 효과, 상대 사용 알림이 필요하다.
- 최대 8명 그룹의 현재 문서·이동 횟수·연결·완주·관전·RETIRE를 감당한다.

### 3.3 상태 화면

- 카운트다운
- 문서/API 로딩
- 연결 끊김과 남은 재접속 유예
- F5 복구 중
- 명시적 나가기 확인
- 아이템 차단·반사·강제 이동
- 개인 완주 후 관전
- 3등 후 2분 grace
- 20분 마감과 RETIRE
- 빈 기록·빈 업적·게스트 제한
- 오류·재시도·무효 경기

### 3.4 관전

- 기본은 선택한 참가자의 실제 플레이 화면이다.
- 전체 경로 비교는 보조 탭/보기다.
- 텍스트 채팅은 없다.
- preset 이모티콘, 사용자별 숨기기, 전체 끄기만 제공한다.

### 3.5 프로필 카드

- 머리·얼굴·의상·손 4부위 조합형 아바타와 아바타 프리셋 편집 화면을 만들지 않는다.
- 시스템 제공 프로필 아이콘/일러스트 4~6종 중 1개를 고르는 단순 선택 UI를 사용하고 사용자 파일 업로드는 제공하지 않는다.
- 프로필 카드에는 대표 칭호 1개, 대표 배지 최대 3개, 프로필 프레임 1개, 프로필 배경 1개를 배치한다.
- 경로 색상·효과, 완주 효과, 관전 이모티콘은 보유 reward inventory에서 선택하되 프로필 카드 본문을 과도하게 장식하지 않는다.
- 상단 내비게이션의 사용자 요약은 닉네임·레벨·대표 칭호 중심으로 유지한다.
- 아이콘 없음, legacy 이미지, 에셋 로딩 실패, 빈 inventory, guest 제한 상태를 각각 디자인한다.
- 모바일에서는 프로필 카드를 먼저 보여주고 보상 inventory는 접을 수 있는 섹션 또는 바텀시트로 제공한다.

## 4. 피해야 할 표현

- SaaS 대시보드처럼 동일 카드만 반복하는 화면
- 본문보다 큰 사이드바·패널
- 과도한 glassmorphism, blur, neon glow
- 모드마다 무관한 장식 일러스트를 크게 배치
- 색상만으로 순위·연결·아이템 상태 구분
- 모바일에서 항상 열린 큰 HUD
- 구현되지 않은 상점·재화·시즌·신고 UI
- 사용자 이미지 업로드, 4부위 조립, 아바타 프리셋 UI
- 실제 기능과 다른 가짜 수치·버튼

## 5. 화면 밀도 원칙

### PC

- 중앙: Wikipedia 본문
- 상단: 시간·목표·이동·순위의 얇은 HUD
- 보조 영역: 빠른 링크, 상대/참가자, 아이템
- 보조 패널은 접거나 폭을 줄일 수 있어야 한다.

### 모바일

- 본문을 기본 전체 화면으로 둔다.
- 핵심 HUD는 한두 줄로 축약한다.
- 참가자·빠른 링크·아이템 설명은 바텀시트로 연다.
- 자주 누르는 링크·아이템·나가기 버튼은 44px 이상이다.
- 바텀시트가 열린 상태에서도 현재 문서와 목표를 잃지 않는다.

## 6. 시각 시스템 산출물

- 컬러 토큰: neutral, accent, success, warning, danger, disabled
- typography: 본문, 문서 제목, HUD 수치, label, button
- spacing/grid/breakpoint
- border/radius/shadow 규칙
- focus/hover/pressed/disabled/loading
- participant status chip
- path node와 movement event 아이콘
- item category와 지속 효과 표현
- 프로필 아이콘·legacy 이미지·reward asset placeholder와 로딩 실패 fallback 규칙
- reduced-motion 대체 규칙

## 7. 화면 산출물

최소 다음 PC·모바일 프레임을 만든다.

1. 인트로/로그인·회원가입·게스트
2. 메인 로비
3. 싱글 모드 선택·오늘의 세 코스
4. 1:1 방 생성·참가·아이템 옵션
5. 그룹 대기실 3~8명
6. 싱글 게임
7. 1:1 비아이템 게임
8. 1:1 아이템 게임
9. 그룹 게임
10. 완주 후 관전
11. 결과·경로 비교·XP·업적 reveal
12. 랭킹
13. 프로필 카드·시스템 아이콘 선택·보상 inventory
14. 일반·히든 업적 도감
15. 복구·연결 끊김·나가기·오류 상태 보드

## 8. 디자인 완료 기준

- 확정 명세의 기능이 화면에서 빠짐없이 찾을 수 있다.
- 모든 버튼은 실제 동작과 연결된다.
- 세 모드의 차이가 설명 없이도 읽힌다.
- Wikipedia 본문이 모든 게임 변형에서 가장 큰 영역이다.
- 8명 그룹과 5개 아이템이 본문을 압박하지 않는다.
- 관전 기본/보조 보기가 구분된다.
- 프로필 카드 장착 slot과 보유/미보유/legacy/error/guest 상태가 구분된다.
- 4부위 아바타·프리셋·사용자 이미지 업로드 UI가 없다.
- PC·모바일·키보드·모션 감소 시안이 있다.
- 개발자가 상태·컴포넌트·breakpoint를 추측하지 않아도 된다.
