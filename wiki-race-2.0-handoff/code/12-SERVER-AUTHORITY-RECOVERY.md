# 기능 패킷 01 — 서버 권위·복구·명시적 이탈

기준 문서: `../01-CONFIRMED-SPEC.md`  
목표: F5 안정성을 유지하면서 경로·승패·결과 조작과 잘못된 이탈 처리를 막는다.

## 1. 확정 규칙

- F5와 일시적 연결 끊김은 명시적 이탈이 아니다.
- 브라우저 뒤로가기·앱 내 나가기는 확인 후 명시적 이탈로 처리한다.
- canonical 문서 ID 기준으로 이동한다.
- 이동 횟수·경로·순위·결과·XP·업적은 서버가 확정한다.
- 같은 이동·완주 요청이 중복 도착해도 한 번만 반영한다.
- stale·역순 Realtime 이벤트가 현재 상태를 되돌리지 않는다.
- 그룹 안정화 RPC/RLS를 근거 없이 재작성하지 않는다.

## 2. 코드 감사 포인트

- 현재 클라이언트가 다음 문서·이동 횟수·전체 경로를 어느 범위까지 직접 전송하는가
- 서버가 현재 문서의 유효 링크인지 확인하는가
- clicked raw title과 resolved canonical ID를 보존할 수 있는가
- finish RPC가 실제 현재 문서와 목표 문서를 검증하는가
- mutation에 expected revision/version 또는 idempotency가 있는가
- F5·visibility change·beforeunload·popstate가 어떤 leave 함수를 호출하는가
- Realtime 구독 재생성·정리와 중복 채널 가능성
- local/session storage와 서버 스냅샷의 우선순위
- disconnect/forfeit/retire finalizer가 서버 시간으로 동작하는가

## 4. 완료 기준

- 조작된 next document와 finish 요청이 서버에서 거부된다.
- 정상 링크 이동은 기존 속도와 UX를 과도하게 해치지 않는다.
- F5 후 현재 문서·경로·이동 횟수·아이템·효과가 복원된다.
- 뒤로가기를 취소하면 게임이 유지되고, 확인하면 정확한 종료 사유가 저장된다.
- 두 번 클릭·재전송·Realtime 재수신으로 이동이나 XP가 중복되지 않는다.
- 기존 그룹 DB/RPC/RLS 테스트와 1:1·싱글 회귀 테스트가 통과한다.
