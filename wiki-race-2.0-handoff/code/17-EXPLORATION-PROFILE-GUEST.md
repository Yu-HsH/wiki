### 5.1 2026-08-14 실제 저장소 기준선

- `profiles`에는 단일 `profile_image_url`만 있고 cosmetic catalog/inventory/equipped 컬럼·테이블은 없다.
- `room_players.profile_image_snapshot`이 그룹·1:1 참가 시점의 이미지 호환 값으로 사용된다.
- `ProfilePage.jsx`에는 `avatars` Storage 사용자 파일 업로드가 있어 확정 명세와 불일치한다. 구현 단계에서 시스템 아이콘 선택으로 교체하되 기존 URL과 storage object를 삭제하지 않는다.
- 프로필/공개 프로필/랭킹/그룹 참가자는 단일 이미지와 글자 placeholder를 서로 다르게 렌더링한다. 공통 fallback 컴포넌트 또는 동일 표시 계약이 필요하다.
- 결과 화면은 프로필 카드 표시를 아직 제공하지 않는다.
- `onboarding_full_avatar`는 로컬 handoff 문서 외 코드·migration에서 발견되지 않았지만 운영 DB와 사용자 기록은 미확인이다.
- 경기 아이템 `inventory`는 별도 시스템이며 이 패킷에서 schema·지급·소비 로직을 변경하지 않는다.

## 7. 기존 싱글 아이템

- 기존 싱글 아이템 기능은 명시적 감사 없이 삭제하지 않는다.
- 새 1:1 공격·방어 카탈로그를 싱글에 그대로 적용하지 않는다.
- 현재 싱글-safe 보조 기능, 저장 형식, F5 복구를 조사한다.
- 최종 디자인은 실제 활성 기능만 노출한다.

## 8. 완료 기준

- 세 오늘 코스가 모든 사용자에게 같은 값으로 안정적으로 제공된다.
- 새로고침과 중복 생성 요청으로 코스가 바뀌지 않는다.
- 코스별 최고 기록과 랭킹 tie-break가 일치한다.
- profile/history가 서버 결과와 일치한다.
- 프로필 아이콘·칭호·배지·프레임·배경 장착이 서버에 저장되고 새로고침·재로그인 뒤 복원된다.
- 프로필·랭킹·그룹 참가자·결과가 같은 프로필 카드 fallback 규칙을 사용한다.
- 기존 `profile_image_url` 사용자와 에셋 오류 사용자가 기본 이미지로 안전하게 표시된다.
- 모바일에서 프로필 카드와 보상 inventory를 사용할 수 있다.
- 사용자 이미지 업로드, 4부위 조합, 아바타 프리셋이 노출되지 않는다.
- guest가 영구 성장 데이터를 만들거나 온라인 통계를 조작하지 못한다.
- guest가 영구 보상이나 장착 상태를 만들지 못한다.
- 기존 경기 아이템 inventory에 회귀가 없다.
- 로그인 사용자의 기존 기록이 마이그레이션 후 보존된다.

```text
Wiki Race 2.0의 랜덤/목표 지정/오늘의 탐험, 기록, 프로필, 게스트 경계를 현재 코드 기준으로 검토해줘.

`01-CONFIRMED-SPEC.md`, `17-EXPLORATION-PROFILE-GUEST.md`, 저장소 감사 결과를 읽고 아직 수정하지 마. 현재 target 생성/검색, daily challenge, ranking, history, profile stats, guest session과 F5 저장 흐름을 추적해.

오늘의 세 공통 코스를 날짜별 immutable snapshot으로 생성하고 코스별 랭킹·최초 XP·올클리어를 지원하는 방안, canonical 경로와 profile/history를 같은 서버 결과에서 읽는 방안, guest가 영구 성장·보상·장착 데이터에 접근하지 못하게 하는 방안을 제안해. 기존 싱글 아이템은 삭제하지 말고 실제 범위를 분리해.

프로필은 4부위 아바타가 아니라 시스템 아이콘 4~6종, 대표 칭호, 대표 배지 최대 3개, 프레임, 배경, 경로/완주 효과, 관전 이모티콘의 프로필 카드로 설계해. 현재 사용자 업로드 코드와 `profile_image_url`/`profile_image_snapshot`을 감사하고 기존 값은 legacy fallback으로 보존해. 업로드·아바타 프리셋·상점·재화는 구현하지 마.

산출물은 현재 흐름, 명세 차이, 데이터/RPC/UI 계약, 마이그레이션·백필, 테스트, 승인 후 Codex 프롬프트 순서로 작성해줘.
```

## 10. 승인 후 Codex 구현 프롬프트

```text
승인된 탐험·오늘의 코스·프로필·게스트 계획을 구현해줘. 세 오늘 코스가 같은 날짜에 모든 사용자에게 동일하게 유지되고, 코스별 최고 기록·랭킹·최초 XP·올클리어가 서버 결과로 동작하게 해.
```
