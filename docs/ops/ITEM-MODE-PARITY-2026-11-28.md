## 서버와 입장 게이트

- `20261127093952_s5_rematch_result_invitation.sql`에 이전 경기 참가자 전용 재경기 입장, S5 참가자와 경로 표시, v4 정산 방 ID, S5 입상 합계 읽기를 둡니다. S5 진행 중인 다른 참가자의 경로는 공개하지 않습니다. 기존 72개 Migration과 정산·아이템·자유 이동 판정은 유지합니다.
- `scripts/item-mode-launch.psql`은 기존 68·70·72 검사에 73을 허용합니다. 73에서는 재경기 Migration 번호와 69~72의 버전이 함께 필요합니다. `open_modes`의 공용 게이트, cron 실행 기록, 정리 작업 건강 상태 확인과 `close_modes`의 동작 순서는 기존과 같습니다.
- 역할 멤버십이 있던 격리 DB에서 옵션을 복원하는 `GRANT` 문에 `t`가 들어가 닫기 작업이 롤백되는 문제도 재현했습니다. 옵션을 SQL boolean 문자열로 출력하도록 수정했습니다. 실제 `close_modes → start_jobs → open_modes`를 실행해 이력 73에서 입장 두 개가 닫혔다가 cron 두 개가 성공한 뒤 열리는 것을 확인했습니다. 공용 게이트는 계속 열려 있었습니다.
- 73의 확장 응답은 키 추가 방식입니다. 최신 클라이언트의 S5 결과 초대와 경기 세부 기록은 73이 배포된 DB에서 동작합니다.
