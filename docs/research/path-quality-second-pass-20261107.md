# Wiki Race 경로 발견 난이도 2차 실험 · 2026-11-07

**상태: 연구 전용 / 실게임 품질 자동 필터 미연동 / DB·Edge 변경 없음.**

## 실제로 읽은 데이터

1. 운영 `game_records`, `group_match_results`에서 **완주 기록 15건**을 무작위가 아닌 결정적 기준(모드별 MD5 정렬)으로 각 3건 표본화.
2. 운영 `wiki_page_snapshots`와 `wiki_snapshot_links`의 **최신 캐시 스냅샷**을 이용해 각 플레이 이동의 *링크 순서상 위치*와 현재 캐시에서 재확인되는 이동 여부를 측정.
3. 공개 위키백과 문서 **11쌍**의 2회 이동 중간 문서를 데이터베이스 링크 그래프에서 조회. 개인 플레이와 무관한 공식 오늘의 도전 후보·공개 문서 조합을 보완해 사례를 확대했다. 중간 문서가 게임 캐시에 존재하고 스냅샷 링크가 확인된 경로만 포함.

**민감정보 최소화:** 저장된 JSON에는 계정/닉네임/방/런 ID, 개별 유저의 상세 경로, 정확한 시각, 페이지 제목을 기록하지 않았으며, 완주 시간은 넓은 구간으로만 보관. 그래프 비교 JSON은 개인 플레이가 아니라 공개 문서들의 연결 결과다.

## 1. 같은 '2회 이동'도 다르다

| 공개 문서 코스 | 캐시의 2회 경로 중간 문서 수 | 첫 링크 가장 앞 순번(0부터) | 해석 |
|---|---:|---:|---|
| 대한민국 → 훈민정음 | 12 | 60 / 1,397 | 한글·조선 등 진입 선택지가 다양함 |
| SQL → 월드 와이드 웹 | 13 | 1 / 438 | 여러 가지 2회 경로; 초기 링크 중 하나로 진입 가능 |
| 음식 → 김치 | 4 | 2 / 587 | 캐시 내 여러 선택지 존재 |
| 김치 → SQL | 2 | 315 / 321 | 유일하게 확인된 중간 지점들은 ISBN·ISSN 계열; 첫 선택 링크가 뒤쪽 |
| 메이플스토리 → GPT (언어 모델) | 0 | - | 캐시에서 **2회 경로를 관측하지 못함** |
| 대한민국 → 한강 | 21 (20개 표본) | 6 / 1,397 | 후보가 20개 수집 한도를 초과함 |
| 서울특별시 → 한강 | 15 | 28 / 1,163 | 다양한 방향에서 중간 문서 선택 |
| 컴퓨터 → 월드 와이드 웹 | 8 | 107 / 185 | 여러 중간 경로 관측 |
| 훈민정음 → 한강 | 5 | 2 / 527 | 첫 번째 선택지가 상당히 앞 순번 |
| 김치 → 한강 | 2 | 163 / 321 | 경로 수가 적고 중간 문서에 따라 선택 난이도 차이 |

| 미국의 하늘에 잘린 달 2 → 2010년 FIFA 월드컵 남미 지역 예선 | 0 | - | 캐시에서 **2회 경로를 관측하지 못함** |

수치는 제한된 게임 캐시의 링크 데이터로 계산했다. 수집은 코스당 최대 20개 중간 문서까지이며, `대한민국 → 한강`은 **전체 21개가 관측되었지만 실제 상세 표본은 20개만 저장했다.** `생물 → 광합성`도 공식 후보 코스에 있으나 이번 최신 스냅샷 자료로는 계산할 수 없어 0건으로 오기하지 않고 표에서 제외했다. **0은 불가능 판정이 아니며**, '첫 링크 순번'은 눈에 보이는 스크롤·위치가 아니라 저장된 앵커 순서다.

실제 완주 예시: `대한민국 → 조선 → 훈민정음`은 2회로 기록되어 있으며, 최신 캐시에서 해당 두 링크 순번은 127/1397, 21/819였다. 최단 경로가 2회여도 사용자가 선택한 경로가 반드시 가장 앞에 있는 링크일 필요는 없다.

반면 `음식 → 김치`는 캐시에서 2회 우회 선택지가 4개 있지만 실제 완주 표본은 **4회 이동**했다. 최단 경로의 존재가 최단 경로를 찾아낸다는 뜻은 아님을 보여주는 사례다.

## 2. 익명화한 완주 기록 15건

| 지표 | 결과 |
|---|---:|
| 표본 수 | 15건 |
| 최신 캐시 기준으로 모든 이동 링크가 재확인된 기록 | 13건 |
| 현재 캐시 자료가 일부 또는 전부 누락된 기록 | 2건 |
| 링크 목록의 뒤쪽 25% 구간(순서 기준)에 해당하는 이동이 하나 이상 있었던 기록 | 4건 |
| 같은 문서를 반복해서 방문한 기록 | 1건 |
| 15분 이상 경과 구간의 기록 | 1건 |

위 **완주 기록은 실제 플레이어가 찾아낸 경로를 보여주는 긍정 사례**이지, '쉬운 코스'라는 정답 라벨이 아니다. 한 기록의 경과시간이 매우 길어도 브라우저를 켜둔 시간이나 휴식일 가능성이 있어 난이도 시간으로 해석하지 않는다. 초기/과거(legacy) 기록은 현재 게임 캐시가 부족할 수 있어, 재검증 실패를 이동 오류로 분류하지 않는다.

## 3. 추가한 분석기

`utils/coursePathEvidence.js`에는 운영과 완전히 분리된 다음 실험 코드가 있다.

- **링크 앵커 순서 지표:** 0부터 시작하는 ordinal/해당 문서 총 링크 수를 비교하되, 실제 화면의 좌표·접힌 영역·마우스 도달 시간을 알 수 없음을 명시.
- **부분 그래프 제한 BFS:** 중간 문서의 저장 스냅샷이 있는 링크만 1~4단계(최대 6까지 인자 허용) 탐색. 탐색 상태·관측 링크·경로 개수 한도를 설정해 비용이 무한정 증가하지 않게 함.
- **다양성 지표:** 관측된 경로 수, 서로 다른 첫 이동 문서 수, 최단 '관측' 이동 길이와 앵커 순서 비용을 따로 기록.
- **관측 불충분을 별도 표현:** 최신 스냅샷이 없거나 탐색 예산이 부족한 경우, '막힌 코스'로 오판하지 않음.
- **게임 판정과 완전 분리:** `verifiedReachable:false`, `autoReject` 해당 없음. 게임 준비 또는 실제 코스 생성에서는 이 모듈을 호출하지 않음.

재현 방법:
```bash
node --test tests/coursePathEvidence.test.js
node scripts/report-path-quality.mjs
node scripts/report-path-quality.mjs --json
```

원본 읽기 전용 SQL은 `scripts/sql/path-quality-historical-readonly.sql`과 `scripts/sql/path-quality-two-hop-readonly.sql`. 전체 프로젝트 테스트는 `npm test`, 정적 빌드는 `npm run build`.

## 4. 이번 실험으로 아직 알 수 없는 것

1. **화면에서 실제로 얼마나 잘 보이는가?** 링크 순서는 시각적 위치가 아니다. 헤더·인포박스·접힌 표·기타 요소와 스크롤을 실제 게임 렌더링 HTML에서 측정해야 한다.
2. **직관적인 클릭인가?** 특정 연결이 주제상 자연스러운지는 제목/순서만으로 판정할 수 없다. 사람 평가가 필요하다.
3. **실패/포기 이유가 코스 때문인가?** 'abandoned'는 접속 종료, 시간 제약, 인터럽트도 포함하므로 실패 라벨로 사용할 수 없다.
4. **모든 경로를 보았는가?** 캐시는 위키백과 전체의 작은 부분이며, 실시간 개정판과 링크 정책이 바뀔 수 있다.
5. **모드별 차이를 어떻게 보정하는가?** 아이템, 경쟁, 힌트, 제한시간 등이 달라 단일 완료 시간만으로 비교할 수 없다.

## 5. 제품 반영 전에 필요한 실험

- **DOM 위치 추정:** 실제 `WikiViewer`에서 사용자가 보는 렌더링 HTML, 제목·링크 표시 텍스트, 표/인포박스/접힘 여부 및 `getBoundingClientRect`를 근거로 가시성 검사. 저장된 `ordinal`과 비교해 어느 정도 상관이 있는지 실측.
- **직관성 평가:** 8~12개 시작·목표 쌍을 3~5명의 플레이어에게 제공하고, 어디를 먼저 클릭할지·막히는 부분을 평가(정답 경로 미노출). 가능하면 '선택의 이유'를 한 줄 기록.
- **어려움과 판정의 구분:** 포기·실패 사례를 별도 수집할 수 있지만 개인별 세션이나 게임 기록을 공개 저장하지 않고, 복구 실패·기술 오류와 구별.
- **검사기 오판율:** 사람이 어렵다고 판단한 조합의 재현율과, 정상 코스를 잘못 어려움이라고 분류하는 비율을 계산한 뒤에만 자동 필터/재추첨 도입.

## 6. 적용 순서 원칙

랜덤 싱글 → 오늘의 도전 코스 확정 전 → 1:1·그룹 경고/선택 지원으로 확장한다. **기존 유저 지정 목표, 이미 시작된 게임, 이미 확정된 오늘 코스는 변경하지 않는다.** Supabase 운영 스키마/Edge Function은 이번 PR에서 수정하지 않는다.
