# Wiki Race 코스 접근성 관측 — 50개 실제 문서 (2026-11-07)

> **분석 전용.** 운영 적용, 서버 코스 재추첨, 자동 차단, DB 변경 없음.

## 자료와 샘플링
- 운영 Wiki Race의 `wiki_page_snapshots`와 `wiki_snapshot_links`를 **SELECT만 실행**하여 수집.
- 측정 시점 운영 스냅샷 2,774건, 저장 링크 513,159건, 스냅샷 문서 2,737종.
- 13개 집중 조사 문서(기존 플레이 코스와 널리 알려진 개념) + 최신 스냅샷 중 `md5(page_id)` 정렬로 뽑은 37개 = **50개**. *위키백과 전체에서 무작위로 선정한 샘플은 아니다.*
- 출발 확장성 = 저장된 문서에서 게임이 서버 판정에 사용할 수 있는 고유 목적지 링크 수.
- 목표 접근성 대리값 = 현재 저장된 다른 **최신 스냅샷 문서** 중 그 문서로 연결된 서로 다른 출발 문서 수. **위키백과 전체 역링크 수가 아니다.**
- '이른 연결'은 스냅샷 링크 `ordinal <= 50`만 세었음. **화면 상단에 보인다거나 사용자가 쉽게 찾을 수 있다는 뜻은 아니다.**

## 발견

1. 사용자 테스트에서 불쾌하게 느껴졌던 `미국의 하늘에 잘린 달 2 → 2010년 FIFA 월드컵 남미 지역 예선`은 출발 링크 17, 목표 진입 1(이른 진입 0)이므로 **우선 사람이 검토할 코스**로 표시할 근거가 있다.
2. 반대로 `GPT (언어 모델)`은 익숙한 주제라도 *이 게임의 저장 스냅샷*에서 진입 연결이 1개뿐이다. `백준 온라인 저지`도 출발 링크가 1개뿐이다. 따라서 캐시 그래프 숫자가 낮다는 이유로 코스를 자동 제거하면 오판할 위험이 크다.
3. 링크 수가 많다고 쉽게 찾는 것도 아니다. 도착에 필요한 실제 클릭 링크의 표시 텍스트·별칭·본문 위치와 초보자 탐색 과정은 관측하지 못했다.
4. 이 데이터에서는 **유효한 경로 존재**와 **사람이 찾기 쉬움**을 결정할 수 없다. 다른 모드까지 확대하기 전에 실제 역링크 API 표본과 사용자 실험이 필요하다.

## 잠정 검사기(연동하지 않음)
- 출발 문서 이동 링크가 20개 미만이면 `FEW_OUTGOING_LINKS`; 2개 이하면 `VERY_FEW_OUTGOING_LINKS`.
- 목표의 캐시 진입 연결이 2개 이하이면 `FEW_INBOUND_IN_CACHED_SAMPLE`; 0이면 `NO_INBOUND_IN_CACHED_SAMPLE`.
- 출발 링크 20개 미만 **AND** 목표 캐시 진입 2개 이하인 조합은 `priority_review`; 하나만 해당하면 `review`로 표시.
- 아직 **모든 결과의 `autoReject`는 false**, `verifiedReachable`는 false. 수치는 연구용 후보값일 뿐 제품 정책이 아니다.
- 수집 누락을 0개라고 간주하지 않는다. `unknown`을 별도로 유지한다.

## 전 모드 적용 시 안전 규칙
- **랜덤 싱글:** 문서 유효성과 스냅샷 판정은 기존과 동일. 추후 확인된 품질 신호로만, 현재 29초 예산과 12번의 문서 추첨 상한을 지키며 **추가적인 후보 재추첨 정책을 별도 PR**에서 시범 적용.
- **오늘의 도전:** 코스 최초 확정 *전* 검증. 이미 확정되거나 누군가 플레이한 코스를 소급 변경하지 않음.
- **목표 지정 싱글 / 1:1 / 그룹:** 사용자가 고른 목표와 서버 판정 결과를 임의로 바꾸지 않고, 경고 또는 재선정 선택지를 제공.
- **오류 시:** Wikimedia API 장애·시간 초과는 '불량 코스'로 취급하지 않음.
