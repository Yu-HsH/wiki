# Wiki Race: 실제 코스 마지막 진입 검사 + 민감 목표 선정 정책 v0 (2026-11-07)

> **연구 전용**. 실제 게임 코드, 링크 이동 권한, 코스 추첨, DB/RPC/Edge, UI는 변경하지 않음. 운영 DB는 SELECT만 사용.

## 1. 근거 데이터

실제 그룹 결과에서 17개 출발·목표 조합(17개 방, 참가자 결과 91건)을 골라, 각 목표로 들어가는 **최신 캐시 스냅샷의 정방향 링크**를 조사했다. 참가자별 경로나 ID, 닉네임, 방 ID, 정확한 시각을 수집 파일에 남기지 않았다.

**주의:** 출처 문서는 최신 Wiki Race 캐시에서만 센 것이며, 외부 위키백과 전체 문서를 조사한 데이터가 아니다. `순번 <50`은 상위 50개 앵커이지 실제 화면 첫 접힘 영역이나 시각적 발견 시간을 뜻하지 않는다. 서로 같은 경기의 참가자는 독립 표본이 아니다.

## 2. 실제로 구현한 연구 검사

`utils/courseEntrywayResearch.js`

- `need_external_backlinks`: 게임 캐시에 진입 출처 없음 → **위키백과 API 재확인 필요**, 자동 탈락 금지.
- `review_calendar_bottleneck`: 캐시에 있는 입구가 생일·연도 등 연대기 페이지뿐일 때 → 상식적으로 도달 가능한 마지막 1칸인지 검토.
- `review_link_visibility`: 관측된 입구가 모두 저장 문서에서 75% 이후의 링크에 있을 때 → **실제 DOM 위치를 별도로 측정해야 함**.
- `GATEWAY_LABEL_ALIAS`: 목표 제목과 실제 클릭 표시 문구가 다를 때 별도 기록. `쿠로바 카이토 → 괴도 키드`처럼 오히려 쉬울 수도 있으므로 **난이도 패널티로 단정하지 않음**.
- `INBOUND_SAMPLE_CAPPED`: 출처가 많아 최대 16개만 상세 관측한 경우 완전한 출처 분포라고 주장하지 않음.
- 모든 결과 `autoReject:false`, `globallyReachable:null`, `difficultyScore:null`로 고정.

**검증의 목적:** 0명 완주 코스의 재검토 우선순위를 잡고, 완주 코스를 무차별적으로 차단하는 오판을 탐지하는 것. **측정된 결과만으로 실제 사람의 체감 난이도와 정확도를 확정하지 않음**.

## 3. 선정적·위험하거나 모호한 목표 문서 — 별도 정책 초안

위키백과 문서는 노골적인 표현을 포함하더라도 의료·역사·학술 자료일 수 있다. 따라서 **단어 금지 목록을 게임 이동 그래프에 그대로 적용하지 않는다**.

별개의 두 판단이 필요하다.

**A. 목표 정체성 / 플레이 성립 여부**
- `pageprops.disambiguation`으로 공식 확인된 동음이의어는 **자동 생성 목표에서는 우선 제외 후보**.
- 같은 이름의 구체적 지역/인물 페이지로 플레이어가 도착해도 동음이의어 문서에는 도착하지 않는 문제가 있다.
- 사용자가 직접 지정했다면 강제 다른 목표로 바꾸지 않고, 동음이의어란 사실을 명시해 재선택 기회를 준다.
- *동음이의어는 위험/선정적 콘텐츠라는 의미가 절대 아니다.*

**B. 콘텐츠 노출 적합성**
- **일반적인 백과사전 주제:** 기본 자동 목표 가능.
- **교육·의학·역사에 관한 민감한 주제:** 노골적인 묘사나 맥락을 실제로 검토한다. 제목만으로 차단하지 않고, 필요시 주제 안내와 재선택 제공.
- **노골적인 성적 표현, 심각하게 잔혹한 묘사, 착취·혐오 선동 등 노출 위험이 명확한 문서:** 근거가 확인된 경우 *랜덤/오늘의 도전/추천/공개방*의 자동 노출에서는 제외하는 안을 우선 검토한다. 사용자 직접 지정/비공개 게임 허용 범위는 플랫폼 정책과 연령 접근 방식 합의가 필요하다.
- **판정 불가능/분류 불명:** 자동 안전 판정(안전하다고 확증하거나 위험하다고 단정)을 하지 않는다. 공적 표면에 노출할 때에는 추가 정보가 필요한지 판단하고 검수 경로를 마련한다.

### 화면별로 달라지는 처리 정책

| 노출 경로 | 동음이의어 | 내용 민감도 확인된 목표 |
|---|---|---|
| 랜덤 목표/오늘의 도전 자동 생성 | 재추첨 또는 다른 후보 추천(향후) | 강한 위험이 확인되면 자동 노출 제외(향후) |
| 공개 그룹/1:1 방 제목·목표 미리보기 | 명확한 목표인지 안내 | 높은 위험의 이름을 별도 검수 없이 공개적으로 노출하지 않음 |
| 사용자가 지정하는 목표 | 강제 교체하지 않고 뜻을 설명 | 교육적 내용 등은 맥락 안내; 고위험은 제품 정책·연령 접근 설정 결정 필요 |
| 게임 중 정상 위키 문서 링크 탐색 | 기존 유효 링크 이동은 유지 | 필터가 서버 권위 링크 이동을 침묵 속에 차단하지 않음. 안전 모드가 필요하면 별도 제품 설계 |

`utils/courseTargetSuitabilityResearch.js`는 이 판단의 **정책 출력만 시뮬레이션**한다. 진짜 차단 기능도, 제목 단어 기반 판정기도 아니다.

**위키백과 공식 API의 한계:** `prop=pageprops`의 `disambiguation`은 동음이의어 확인에 유용하지만, `prop=categories`의 분류 이름과 표제어는 그 자체로 콘텐츠의 연령/위험 등급이 아니다. <https://www.mediawiki.org/wiki/API:Pageprops>, <https://www.mediawiki.org/wiki/API:Categories>

## 4. 모드 공통 적용 시 단계별 검증

1. 지금: 실제 그룹 사례 17개 분석기와 문서 적합성 정책을 **프로덕션에서 호출하지 않는 연구 코드**로 분리.
2. 위키백과 메타데이터 확인: 민감해 보이는 실제 목표 문서의 `pageprops`/상위 분류를 소량 조회하고 누락·오판 확인. 단어 목록만으로 판정하지 않음.
3. 실제 목표 진입 실험: 위키백과 공식 역링크 출처가 사용자가 떠올리기 쉬운 일반 문서인지, 해당 링크가 WikiViewer에서 실제 보이는 위치인지 확인. 같은 단계라도 서버 권위가 인정한 링크만 사용.
4. 자동 생성 모드의 안전한 후보 처리: 비용이 적은 공식 동음이의어 판별부터 실험하고, 기존 29초 예산·12회 추첨 상한과 에러 정책을 유지. 기존 목표 기록 소급 변경 없음.
5. 더 높은 정확도가 입증된 후에만 랜덤/오늘/대전/그룹의 선택 규칙에 단계적으로 반영하고 별도 운영 승인.

## 5. 현재까지 불확실한 것

- 자동 민감도 판별 정확도(정답 라벨/실제 정책 아직 없음), 위키백과 공개 분류가 그 기준과 얼마나 일치하는지.
- 동일 사용자에게 콘텐츠가 첫 화면에서 보이는 정도와 연령층(현재 서비스가 미성년자를 인증·구분한다는 근거 없음).
- 각주, 문서 끝부분 출처·라이선스 문구 등에서 생긴 실제 플레이 연결이 유효 게임 링크 정책상 어떻게 보이는지.
- 상대방의 완주·타이머·강제 이동·기권이 기록에 개입한 정도.
