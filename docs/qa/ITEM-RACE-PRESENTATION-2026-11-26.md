## 서버 계약이 필요한 항목

- 두 모드의 **3·2·1 동시 출발**에는 참가자 모두에게 미래의 시작 시각이 먼저 전달돼야 합니다. 현 계약은 v4가 요청 처리 시각, S5가 경기 초기화 시각에 즉시 시작합니다. 이동 허용, 경기 시간, 첫 보급과 XP의 기준으로 같은 시각을 사용하려면 예약 상태와 시작 시각을 두 서버에 추가해야 합니다. 이 변경은 서버 시작 직후 기존 일반전 시작음 `go`와 짧은 화면 표시를 재생합니다. 늦게 접속하거나 새로 고침하면 지난 시작음은 생략합니다.
- S5 후보 추첨은 고정된 `start_snapshot_id`, `goal_snapshot_id`, `wiki_course_pages`로 시작 초기화와 링크 검증을 하는 계약에 걸립니다. 일반 그룹과 같은 후보 제출 및 준비 취소에는 후보 기록, 코스 고정 시각과 링크 검증을 포함한 별도 계약이 필요합니다.
- S5 대기방 응답에는 상대 계정 및 방장 식별자와 출발 문서 제목이 없습니다. 전체 참가자 프로필 열기, 시작 가능 전 방장 배지, 출발 문서 미리보기에는 별도 응답 필드가 필요합니다. v4 참가자 슬롯을 실제로 비우는 대기방 퇴장 명령도 별도입니다.

## 제품 빌드 실전 검증

기준 `37256996`에 이 PR 변경을 적용한 작업 트리입니다. 2026-11-26 KST에 `npm test` 937/937과 `npm run build`를 통과했습니다. 빌드에서 기존 큰 번들과 React Router 모듈 지시어 경고가 남았습니다.

- 격리 Docker Supabase의 마이그레이션 이력 68개를 확인했습니다. 실제 GoTrue 인증 계정 5개, 독립 Chromium 세션, 프로덕션 모드 빌드와 실제 Wikipedia 문서로 진행했습니다. 양쪽 패링 등 분기 재현에 필요한 아이템만 격리 DB에서 지정했습니다. 이동·완주·XP·재경기는 제품 계약으로 실행했습니다.
- v4는 UI 방 생성·참가, Wikipedia “훈민정음” 후보의 저장과 상대 반영, “한글 → 훈민정음” 완주를 확인했습니다. 첫 경기의 출발 문서는 기존 시작 RPC로 지정했고, 재경기에서 제품의 무작위 출발 버튼을 확인했습니다. 두 화면의 서버 시작 시각과 첫 보급 `+20초`, 키보드·호버·터치, 반사, 보호막 차단, 룰렛 회전·감속·결과, 패배 문구, F5 전후 XP를 확인했습니다.
- S5는 “숲 → 나무 → 광합성” 등록 코스에서 세 계정의 READY 및 UI 시작, 같은 서버 시작 시각, 두 공격의 동시 경고, 터치 패링과 먹물, 첫 완주자의 관전과 새로고침, 최종 1~3위와 방장 재경기를 확인했습니다. 시간 만료 뒤 서버 상태를 재조회하면 먹물 효과의 처음부터 소리가 따라왔습니다.
- v4의 “한글” PC와 S5의 “숲” 모바일에서 상단·중간·하단의 먹물 효과 레이어가 HUD와 하단 도구 영역 사이에 머무는 것을 측정했습니다. 모바일 320px과 390px에서 수평 넘침도 확인했습니다.
