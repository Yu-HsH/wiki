# 두 아이템전 서버 계약 후속

PR #66을 기반으로 쌓은 후속 브랜치입니다. 화면 보완 PR은 기존 68개 Migration 위에서 단독으로 동작합니다. 여기에 추가한 Migration 두 개는 새 클라이언트가 예약 출발을 요청할 때 적용되는 계약이며, 기존 시작 요청과 고정 코스 경로도 유지합니다. 기준은 PR #66의 모바일 보완 작업입니다. 검증 날짜는 2026-11-26 KST입니다.

| 계약 | 구현 |
| --- | --- |
| v4 예약 출발과 정상 퇴장 | 기존 시작 검증, 엔진, XP 경로를 예약 시각과 함께 사용합니다. 출발 시각 전에는 보급 정보와 경기 명령을 잠급니다. 대기 중 게스트가 나가면 자리가 비고, 방장이 나가면 방 코드가 닫힙니다. 같은 퇴장 요청은 같은 결과를 반환합니다. |
| S5 시작·준비 취소 | 방 잠금과 기존 버전으로 예약·준비 취소·합류 경합을 정리합니다. 서버가 4초 뒤 시각을 개방하고 두 모드가 일반전의 3·2·1 화면과 효과음을 재사용합니다. S5는 예약 시각이 지난 첫 상태 읽기에서 같은 시각을 기준으로 세션·경기 기한·초기 보급을 한 트랜잭션에서 초기화합니다. |
| S5 출발·목표 선택 | 현재 방에 등록된 문서에서 참가자가 한 건씩 제출하거나 회수합니다. 서버는 고정 그래프의 방향과 링크 검증을 따라 도달 가능한 서로 다른 후보 쌍을 추첨하고 경기 동안 고정합니다. 후보가 없으면 기존 기본 코스를 사용합니다. 유효한 쌍이 없으면 시작을 거절합니다. |
| 방장·프로필 | 방원 응답에 방장 여부, 공개 프로필 ID와 닉네임만 추가합니다. 프로필 카드는 기존 프로필 표시를 재사용합니다. |
| S5 비공개 알림 | 탈취된 원본 지급과 최종 함정 기록을 근거로 피해자 또는 설치자 응답에만 이벤트를 추가합니다. 보호막으로 차단된 함정과 발동된 함정을 구분합니다. 새로고침은 지난 이벤트를 재생하지 않습니다. |
| 정확한 보급 ID | v4는 자신의 보급 라운드와 현재 보유한 지급 ID를 내려줍니다. S5는 현재 보급 결과의 원본 라운드와 수신자·참가 epoch에 대응하는 실제 지급 ID를 내려줍니다. |

등록 그래프 밖의 Wikipedia 문서, 새 그래프 생성과 코스 등록·관리, 기존 등록 문서의 개정 전환은 별도 작업 단위입니다. 현재 기능은 기존 등록 스냅샷과 링크만 사용합니다.

## 격리 환경 검증

2026-11-26 KST에 PR #66 기준 `bfe4c9d` 위의 서버 작업 트리에서 두 Migration을 68개 적용 상태의 로컬 Docker DB에 추가 적용했습니다. GoTrue 계정 5개와 Chromium에서 실제 Wikipedia 경로로 확인했습니다.

- 두 모드에서 3·2·1이 나타났고 참가자들에게 같은 예약 시각이 표시됐습니다. v4 예약 중 기권과 보급 조회, S5 예약 중 준비 취소와 세션 초기화가 막혔습니다. 시작 후 경기 시각과 지급 ID가 일치했습니다.
- v4 게스트 퇴장 재시도, 동일 코드 재입장, 방장 퇴장 시 재입장 차단을 확인했습니다. S5는 방장·프로필 표시, 준비 취소 뒤 시작 비활성화, 후보 추첨, 기존 링크 검증을 통한 추첨된 목표 완주를 확인했습니다.
- S5 탈취는 격리 DB에서 성공하는 난수 입력을 골라 실제 엔진을 호출했습니다. 함정은 실제 설치와 피해자 링크 클릭으로 발동했습니다. 두 알림이 지정된 수신자 화면에만 나타났으며 F5에서 다시 재생되지 않았습니다. 보호막으로 막힌 함정 알림의 문구와 중복 방지는 단위 테스트로 확인했습니다.
- 단위 테스트 940/940과 제품 빌드가 통과했습니다.

Migration 적용 명령은 이미 68개가 적용된 격리 로컬 스택을 기준으로 합니다.

```sh
npx supabase migration up --local
npm test
npm run build
```

운영 데이터와 배포는 별도 승인 대상입니다.
