## 2. 구현 디자인

상단은 목재 공통 헤더와 양피지 대전 정보면이다. 제목은 **1:1 대전 준비**, 방 코드·44px 복사 버튼·아이템전 여부·방 나가기·기존 연결/3초 재조회 상태를 모았다. 불필요한 브리핑 단락을 제거했다. 버튼은 모두 기존 이벤트 경로를 사용한다 [코드: RoomPage].

중앙은 방장 / VS / 상대 카드다. 1440·768·390px은 좌우 비교, 320px은 세로로 배치한다. 기존 서버 프로필 슬롯을 전달하는 **ProfileCard density FULL**을 사용한다. 기존 1:1은 ProfileAvatar만 따로 렌더링해 프레임을 그리는 공용 카드 레이어가 빠져 있었는데, 이번에는 공용 프레임·아이콘·칭호·배경 표시 규칙을 그대로 재사용했다. 새로운 장착 ID·조회·이미지를 만들지 않았다. 긴 이름과 칭호는 줄바꿈하며 자르지 않는다 [코드: ProfileCard, profileCard.js, RoomPage].

중앙 중복 목표를 제거하고 아래 **공통 목표 패널 하나**에 서버 저장 목표만 금색으로 표시한다. 변경 입력을 열어도 기존 저장 목표를 유지하고 ‘기존에 저장된 목표’로 구분한다. 검색어·검색 결과는 별도이며 입력만으로 확정 표시하지 않는다. 미확정·검색 중·저장 중·저장 실패·확정·참가자 읽기 상태를 표시한다. 출발은 ‘경기 시작 시 결정’ 안내만 유지한다. 하단의 canStart/disabled·방장 CTA·참가자 대기는 기존 조건 그대로다. 고정 CTA는 추가하지 않았다 [코드].

기존 ProfileCard의 클릭 경로를 유지하고, 1:1에서 열리는 UserProfileModal을 기존 ExpeditionDialog로 감싸 대화상자 이름·포커스 가두기·Escape·포커스 복귀를 적용했다. UserProfileModal 자체나 다른 화면의 모달은 수정하지 않았다. 닫기 버튼과 긴 닉네임/레벨의 겹침을 1:1 범위 CSS로 막았다 [코드].

## 9. 남은 문제·미확인

실제 Supabase의 권한/동시성·실서버 Realtime·실장착 사용자 계정·실제 스마트폰/Safari/Firefox·OS 글꼴 배율은 미검증이다. 키보드는 높이를 줄인 브라우저 검증이며 실제 가상 키보드를 띄운 것은 아니다. 복사는 브라우저 API의 성공/거부 fixture로 확인했다. 기존 대형 청크 경고는 범위 밖이다. CSS의 :has는 사용 브라우저 지원 범위 확인이 필요하다. CURRENT의 통합 갱신은 통합 세션에 인계한다.

## 10. 그룹에 재사용 가능한 것

A+ 역할 변수, 목재 헤더·양피지 패널·금색 목표·파란 CTA, 44px 조작부, 실제 ProfileCard 프레임 표시, 프로필 대화상자 접근성, 상태/오류 문구의 위계를 재사용할 수 있다. **그룹은 아직 수정하지 않았다.** 다음에는 로컬 후보 선택과 서버 제출/READY를 구분하고, 기존 방장 권한·전원 READY·서로 다른 후보 ID 조건·F5 복원을 유지해야 한다. 1:1의 READY 없음·공통 목표 하나 모델을 그룹에 그대로 적용하지 않는다.
